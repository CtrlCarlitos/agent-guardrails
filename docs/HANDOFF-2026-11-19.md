## Mechanics that cost time on 2026-11-19 (all measured, none guessed)

- **Stale-base dance.** Branch protection requires 3 strict status checks
  against current main; main moves fast (two agents shipping). A green PR
  goes BEHIND the moment the other agent merges. Recovery: `git merge
  origin/main` into your branch, push (a merge commit — **never
  force-push**, P1-denied), re-watch, merge. Never stack PRs; never
  rebuild on the other agent's branch.
- **Merges are the operator's.** The engine gates `gh pr merge` for agent
  sessions ("merges into the target branch under the operator's token").
  The flow that worked all day: watch with `gh pr checks N --watch`
  (background), say **"merge now"** with the exact command, operator runs
  it in their terminal. Race warning: a merge before the last check
  concludes bounces ("3 of 3 required status checks are expected") — wait
  for the signal. Repo auto-merge is disabled; the operator may enable it
  (Settings → Pull Requests) to end the timing game.
- **More engine gates to expect:** `git branch -D` (squash-merged branches
  are "unmerged" to git — ask the operator, batch the request),
  `git worktree remove` (unless ADR-0039 provenance applies — see below),
  `git commit --amend`, and multi-statement/`$_` shell lines (P3 asks; use
  script files under `C:\Users\lab\AppData\Local\Temp\opencode\`, run via
  `pwsh -NoProfile -File`).
- **ADR-0039 (worktree provenance, #638).** A session may remove the exact
  worktree it created: same-session `git worktree add` audit record, exact
  path after canonicalization, 24h lookback → the P2 ask becomes an allow
