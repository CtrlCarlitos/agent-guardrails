# Issue #349: exact-action approval verification

## Root cause and implementation

Codex CLI 0.160.0 cannot return a native PreToolUse Ask. The existing
command-only grant cannot authorize `apply_patch`: the normalized tool is
Edit and its shell command is empty. Generic `explain` also promised
conversational approval, including for parser backstops and post-edit findings.

Grantable pre-execution commands and patches now create private exact-action
requests. An interactive terminal grant or authenticated broker completion
permits one matching retry before the original 15-minute expiry. Issuance and
consumption are locked and audited. The bounded store rejects lossy UTF-8
serialization and is protected against agent reads and writes. Body text is
absent from broker state and issuance audit. The browser refuses a passkey
ceremony when the complete pending action cannot be reviewed.

Codex `explain` uses the adapter's pre-approval or post-feedback guidance.
Post checks create no request and explicitly report that the tool already
ran. Deny and NeverGrantable remain invariant.

## Measured focused checks

Final `go vet ./...` and `go test -p 2 ./...` passed on Windows with Go
1.26.0. Linux / WSL Go 1.26.0 vet and the full suite with `-count=1` also
passed. The existing command-grant guidance assertion was preserved and
the regression was fixed in the renderer, rather than in its expectation.

Windows tests passed for exact binding, one-use concurrency, expiry,
revocation, failed issuance and consumption audits, store corruption and
capacity, read/write protection, terminal approval/decline, passkey enrollment
and completion attribution, broker body privacy and binding validation,
browser reviewability, and Codex pre/post explain guidance. The operator added
the new package to Windows CI; the visibility regression passed unchanged.

## Native Linux / WSL

A deterministic local Responses fixture used installed Codex and a simulated
operator terminal in an isolated POSIX PTY. No model service or production
grants were involved. The probe and terminal ceremony exited 0; six pre-hooks
and two post-hooks were observed. Final report: `codex-action-grant-krimaz4z`.

Snapshots showed no workflow after the original Ask or changed patch, the
exact approved contents after the identical retry, and a blocked second retry.
A malformed Go edit was written before post-edit lint feedback; a denied
self-configuration patch did not execute.

The first run put private state on DrvFS, which reported 0777 despite chmod.
The store failed closed. Only the disposable operator fixture moved to the
native filesystem; privatefs expectations were not weakened.

## Native Windows limitation

The unattended probe exited nonzero. Six pre-hooks ran and blocked patches
left the target absent. An operator-terminal ceremony was unavailable, and
the allowed malformed-Go edit failed to write, leaving no post-hook.
Report: `codex-action-grant-7bj7gaih`.

`--operator-terminal` supports review and approval in an actual operator
console, with isolated fixture config and no production grants. That Windows
run remains pending. The Windows sandbox/write-context blocker from #169 is
also unresolved. The required native Windows approval-and-edit acceptance is
not green; this work remains a draft until it is established or the operator
explicitly revises the scope.
