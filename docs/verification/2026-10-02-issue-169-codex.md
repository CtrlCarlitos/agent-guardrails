# Issue #169: native stdin probe evidence

Runtime measured in this session: Codex CLI 0.160.0. No engine contract was
relaxed. In particular, `write_stdin` remains unsupported for reliable
pre-execution mediation (ADR-0014).

## Harness corrections

The Windows fixture's PowerShell `$input` pipeline was not a suitable live
terminal process. The probe now uses a fixed text-line capture command that
is separately checked on Windows. Fixture artifacts live under the checkout,
outside system temp, and native transcripts are retained.

The provider obtains the actual session ID from the interactive command's
output. An exited or rejected command has no live ID: the comparison skips
the three stdin calls, reports the startup output and exits nonzero. It never
fabricates process ID zero for the unrestricted comparison. The restricted
probe still deliberately forces unsupported tool calls to verify rejection.

## Linux / WSL

The final unrestricted native comparison exited 0, started a live process,
delivered the exact fixture line, exited cleanly after EOF and applied the
ordinary patch. Two PreToolUse hooks were observed, with zero stdin hooks.
Report: `guardrail-codex-native-x60hqhh7`.

A preceding run during concurrent full-suite verification timed out at the
patch hook after stdin delivery; that run exited nonzero and was retained as
failure evidence. It is not included in the successful comparison.

## Windows

The operator independently ran the original comparison from a normal
terminal. It exited nonzero: no live process was available, all fabricated
stdin calls failed with `Unknown process id 0`, and the allowed patch could
not write its fixture file. Report: `guardrail-codex-native-rqhel2ss`.

A read-only native observer using the unelevated sandbox found that all six
requested shell/workdir variants actually ran from
`C:\Program Files\PowerShell\7`, despite the fixture cwd in the hook input.
Report: `codex-execution-contract-p8w4gh4_`. The evaluated-directory guard
correctly rejected that mismatch; removing it would hide an execution-context
failure.

The preferred elevated sandbox was also attempted with a disposable Codex
home. All six process creations failed while initializing the sandbox's
private credential state. Those credential files were not inspected or
changed. Report: `codex-execution-contract-i3mbq0ij`.

The corrected unrestricted probe reports `stdin_process_started: false` and
`skipped_calls: [1, 2, 3]` instead of sending to ID zero. Its Windows native
comparison remains inconclusive and exits nonzero. Windows #169 is still
blocked on native execution context and sandbox startup; these harness
corrections do not close the issue or establish stdin hook coverage.
