# ADR-0037: Write seams — where writes are authorised and why

## Status

Proposed (for operator review, 2026-11-15; tracks [#113](https://github.com/CtrlCarlitos/agent-guardrails/issues/113), originally filed under the provisional number ADR-0022 before [ADR-0022](./0022-degraded-mode-floor-fallback.md) took that slot). Cross-references [ADR-0010](./0010-operator-scoped-loosening.md), [ADR-0012](./0012-static-analysis-boundary-and-shape-threshold.md), [ADR-0021](./0021-windows-approval-broker.md), [ADR-0022](./0022-degraded-mode-floor-fallback.md), [ADR-0027](./0027-operator-issued-grants-authorize-one-exact-command.md), [ADR-0028](./0028-settings-files-are-user-owned-hooks-only.md), and [ADR-0033](./0033-operator-approvals-default-to-a-prompt.md).

## Context

Write containment, self-configuration protection, git-hook protection, and secret protection have accrued across five rule families (`P1`, `P2`, `P3`, `P4`, `P5`), four plane adapters, and the two-file policy merge (`guardrail.toml` Overlay and `waivers.toml` Operator config). Because each carve-out or denial landed in its own PR (#112, #146, #255, #357, #416, #435, #512, #542/#550), there was no single normative reference answering:

1. **Every path category on a host**: whether an agent session may write it (`allow`, `ask`, or `deny`), why that seam exists, whether the check depends on the session's `RepoRoot`, and which function in `internal/` enforces it.
2. **How write seams behave when the Engine is unreachable**: how [ADR-0022](./0022-degraded-mode-floor-fallback.md)'s capability table and [ADR-0028](./0028-settings-files-are-user-owned-hooks-only.md)'s floor retirement interact per plane.
3. **The normative request/grant handshake** between a repository's `guardrail.toml` Overlay and the machine's `waivers.toml` Operator config, plus the single-file exception for operator-issued command grants ([ADR-0027](./0027-operator-issued-grants-authorize-one-exact-command.md)).
4. **The normative three-tier secret classification** (`secret_dirs`, `secret_globs`, `secret_ask_globs`, and `secret_allow`), including how reads, writes, and mentions in opaque interpreter text are judged.

## Decision

### 1. Master write-seams table

Every write attempted through a native file mutation tool (`Edit`, `Write`, `MultiEdit`, or a `CapabilityMutation` MCP tool; `isWriteToolCall` in `internal/engine/rules_path.go:36-49`) or a shell command (`writeCandidatesAnalysis` in `internal/engine/rules_path.go:636-672`, `checkDestinationWrites` in `internal/engine/rules_bash.go:965-1014`, `checkAskTierWithFindFSExemption` in `internal/engine/rules_bash.go:1861-1875`, and `checkRmRf` in `internal/engine/rules_bash.go:1309-1353`) is evaluated against the seams below. All applicable checks run and the highest-severity verdict wins (`Decision.Severity()` in `internal/policy/policy.go:58-70`: `allow < ask < deny`).

### 2. How write seams interact with degraded mode and Engine outage

[ADR-0022](./0022-degraded-mode-floor-fallback.md) defined the capability-based fallback contract when the Engine cannot be reached, and [ADR-0028](./0028-settings-files-are-user-owned-hooks-only.md) retired the generated declarative permission floor on Claude Code, OpenCode, and Antigravity while keeping Codex's floor as primary enforcement until Codex pre-hooks dispatch on Windows. Consequently, write-seam enforcement during an Engine outage depends on the plane:

| Plane | Normal operation (Engine reachable) | Engine unreachable / spawn failure | Declarative floor status ([ADR-0028](./0028-settings-files-are-user-owned-hooks-only.md)) | Enforcing code |
|---|---|---|---|---|
| **OpenCode** | Plugin calls Engine (via daemon or `spawnSync` with retries); full Section 1 table applies | Plugin enters ADR-0022 degraded mode (`internal/genconfig/opencode_plugin.js`): **`command`, `web_fetch`, `web_search`, `delegation`, `external`, `deny`, `unknown` fail closed (deny)**; **`read_discovery` and `mutation` degrade to allow** so the session is not deadlocked on file edits during a transient spawn timeout, logged to `plugin-failures.log` and `plugin-timing.jsonl` | Generated permission floor retired in ADR-0028 Phase B (#357); OpenCode V2 config sets `external_directory: ask` (`internal/genconfig/opencode.go`) | `internal/genconfig/opencode_plugin.js`; `internal/genconfig/opencode.go` |
| **Claude Code** | `PreToolUse` hook calls Engine; full Section 1 table applies | Claude Code silently no-ops a failed hook spawn (#151); calls proceed unmediated during the outage window, surfaced loudly by `SessionStart` posture and `guardrail doctor` | Generated permission floor and `allow-baseline` retired in ADR-0028 Phase C (#357, #531); user-owned `permissions.deny`/`ask` in `~/.claude/settings.json` remain untouched | `internal/genconfig/claude.go`; `cmd/guardrail/doctor.go` |
| **Antigravity** | `PreToolUse` hook in `~/.gemini/config/hooks.json` (`matcher: "*"`) calls Engine; full Section 1 table applies, including `tc.PermittedRoots` for the session's `brain/<conversationId>` dir | Antigravity has no declarative permission floor ([ADR-0008](./0008-antigravity-no-declarative-floor.md)); if the binary cannot be spawned (e.g. Windows spaced path without 8.3 short name, #358), the hook fails and `setup` / `plane enable` / `doctor` warn on stderr | Never had a floor (ADR-0008; ADR-0028 Phase A) | `internal/genconfig/antigravity.go`; `cmd/guardrail/doctor_antigravity_spawn.go` |
| **Codex** | Native hooks in `~/.codex/hooks.json` + 32-rule escalation floor in `~/.codex/rules/guardrail.rules`; asks become structured blocks ([ADR-0014](./0014-codex-native-hooks-and-blocked-asks.md), [ADR-0031](./0031-codex-windows-launcher-returns-structured-blocks.md)) | On Windows where Codex pre-hooks do not dispatch (`openai/codex#24453`), the native escalation floor (`CodexRules()`) is the active gate | **Exception plane (ADR-0028 Phase D)**: keeps its generated floor until `doctor` observes runtime hook dispatch | `internal/genconfig/codex.go`; `internal/genconfig/codex_rules.go` |

### 3. Normative request / grant tables (Overlay $\leftrightarrow$ Operator config)

A repository's committed `guardrail.toml` (**Overlay**) may tighten policy or add in-repo `safe_roots` on its own, but **any relaxation of the Base policy requires a matching grant in the machine-scoped Operator config (`waivers.toml`)** ([ADR-0010](./0010-operator-scoped-loosening.md)). Neither file can be written by an agent session (`P5.self-config`, Section 1).

#### 3a. Two-file handshake (`<repo>/guardrail.toml` $\leftrightarrow$ `waivers.toml` `["<cleaned-abs-repo-path>"]`)

Enforced by `policy.Merge` (`internal/policy/merge.go:12-157`) and `OperatorConfig` (`internal/policy/operator.go:21-44`, `189-247`):

| Capability / slot | Overlay request (`<repo>/guardrail.toml`) | Operator config grant (`waivers.toml` under `["<abs-repo-path>"]`) | Behaviour when both agree | Behaviour when Operator grant is absent or invalid | Enforcing code |
|---|---|---|---|---|---|
| **Rule additions** | `[[rules]]` with `decision = "ask" \| "deny"` | *None required* (tightening only; `allow` is rejected at load with an error) | Appended to active policy rules; combined with built-in verdicts by severity ([ADR-0026](./0026-built-in-and-overlay-verdicts-combine-by-severity.md)) | N/A (`allow` rules fail `Merge`) | `internal/policy/merge.go:66-71` |
| **Additional secret globs** | `[slots].secret_dirs`, `secret_globs`, `secret_ask_globs` | *None required* (tightening only) | Appended to Base secret slots | N/A | `internal/policy/merge.go:62-65` |
| **In-repo safe roots** | `[slots].safe_roots = ["./tmp", ...]` | *None required* (no `safe_roots` grant exists in `waivers.toml`) | Added to `Slots.SafeRoots` **only if** both lexical and symlink-resolved paths stay inside `repoRoot` | Any entry that escapes `repoRoot` lexically or through symlinks is **DROPPED** with a policy warning and cannot be granted | `internal/policy/merge.go:73-95` |
| **Rule waivers** | Top-level `waive = ["<rule-id>", ...]` (or per-rule `waive`) | `waive = ["<rule-id>", ...]` | `Policy.Waived[ruleID] = true` (with an audit/doctor warning), **except** the three immutable fail-closed backstops (`tokenize-failed`, `panic-recovered`, `P3.unresolved`), which can never be waived | Request is **DROPPED** with `NOT authorized` warning (`can never be waived` for `neverWaivable`); rule remains enforced | `internal/policy/operator.go:15-19` (`neverWaivable`), `217-223` (`AllowsWaiver`); `internal/policy/merge.go:136-148` |
| **Shell egress allowlist** | `[slots].egress_allowlist = ["<host-or-pattern>", ...]` | `egress_allowlist = ["<exact-entry>", ...]` | Exact case-sensitive entry added to `Slots.EgressAllowlist` (`*` and `**` are always dropped even if listed in both) | Request is **DROPPED** with `NOT authorized` warning | `internal/policy/operator.go:235-238` (`AllowsEgress`); `internal/policy/merge.go:97-108` |
| **Web research hosts (`guardrail fetch`)** | `[slots].web_hosts = ["<hostname>", ...]` | `web_hosts = ["<hostname>", ...]` (or top-level `[web_hosts] global = [...]`) | Canonical lowercase hostname validated by `ValidateWebHost` and added to `Slots.WebHosts` | Request is **DROPPED** with `NOT authorized` warning | `internal/policy/policy.go:135-150` (`ValidateWebHost`); `internal/policy/operator.go:240-247`; `internal/policy/merge.go:45-49`, `109-116` |
| **File-secret exemptions** | `[slots].secret_allow = ["<glob>", ...]` | `secret_allow = true` | Overlay's `secret_allow` globs are appended to `Slots.SecretAllow` (exempts matching `secret_globs` and `secret_ask_globs` files, **never** `secret_dirs`) | Request is **DROPPED**; Base `secret_allow` (`**/.env.example`, `**/.env.sample`, `**/*.pub`) remains in force | `internal/policy/operator.go:225-228` (`AllowsSecretAllow`); `internal/policy/merge.go:118-125`; `internal/engine/rules_path.go:245-250` |
| **Audit log redirect** | Top-level `audit_log = "<path>"` | `audit_log = true` | `Slots.AuditLog` is set to the Overlay's path | Request is **DROPPED**; default machine audit log path is retained | `internal/policy/operator.go:230-233` (`AllowsAuditLog`); `internal/policy/merge.go:127-134` |

#### 3b. Single-file operator-only settings & grants in `waivers.toml` (no Overlay counterpart)

These settings live exclusively in `waivers.toml` because they express machine-wide operator posture or single-command interactive authorizations that must not be staged in version control ([ADR-0027](./0027-operator-issued-grants-authorize-one-exact-command.md), [ADR-0032](./0032-native-web-research-is-an-operator-selected-posture.md), [ADR-0033](./0033-operator-approvals-default-to-a-prompt.md)):

| `waivers.toml` key | Scope | What it authorizes | Invariants & bounds | Enforcing code |
|---|---|---|---|---|
| `approval = "prompt" \| "passkey"` | Machine-wide (top-level scalar) | Selects whether operator actions approve via host ask / terminal `[y/N]` (`prompt`, default) or WebAuthn ceremony (`passkey`) | Any other value rejects the whole `waivers.toml`; an unreadable file fails closed to `passkey` mode | `internal/policy/operator.go:48-61`, `135-141` |
| `[web_research] enforcement = "on" \| "off"` | Machine-wide (top-level table) | `"off"` allows native `WebFetch`/`WebSearch` tools without redirecting to `guardrail fetch`; default (`""` or `"on"`) enforces `guardrail fetch` | Set via `guardrail web-research on\|off` with operator approval | `internal/policy/operator.go:142-144`; `internal/policy/merge.go:44` |
| `[web_hosts] global = ["<hostname>", ...]` | Machine-wide (top-level table) | Authorizes canonical hostnames for `guardrail fetch` across all repositories on the machine | Each entry must pass `ValidateWebHost` | `internal/policy/operator.go:145-149`, `240-242`; `internal/policy/merge.go:45-49` |
| `[["<abs-repo-path>".grant]]` (`rule_id`, `command`, `uses`, `expires_at`) | Exact `(repoRoot, ruleID, command)` triple | Rewrites an **Ask** into an **Allow** (`ask-allowed-by-operator-grant`) for one exact command string | **Ask only** (never relaxes a Deny); default `uses = 1` (absent/0 is spent), default expiry `30m` clamped to `MaxGrantExpiry = 24h`; **never grantable** for `NeverGrantable` rules (`capability-external`, `capability-web-search`, `unknown-native-tool`, `P1.power`, `P1.net-stack`, `tokenize-failed`, `panic-recovered`, `P3.unresolved`) | `internal/policy/grants.go:21-181` (`NeverRelaxable`, `NeverGrantable`, `CommandGrant.Live`, `AllowsCommand`) |

### 4. Normative secret-tier table

Secret protection (`P4`) applies symmetrically to **reads, writes, deletes, and copies** on both native file tools and shell commands (`parsePrivatePathsAnalysis` in `internal/engine/rules_path.go:120-183`), and is evaluated across every candidate path form: home-stripped (`~/` removed), Windows `%USERPROFILE%` / `$env:USERPROFILE` expanded, and symlink-resolved through existing ancestors (`pathCandidateForms` in `internal/engine/rules_path.go:274-285`).

| Secret tier | Policy slot (`internal/policy/base.toml`) | Representative patterns in Base policy | Verdict & `RuleID` | Waivable / overridable? | Enforcing code |
|---|---|---|---|---|---|
| **1. ## Consequences

- Every authorised write seam outside the repository, every self-config and git-protected denial inside or outside the repository, the two-file Overlay $\leftrightarrow$ Operator config handshake, and the three secret tiers now have a single normative table with exact `file:func` citations.
- `docs/OPERATIONS.md` ("Things that look like bugs and aren't") and `README.md` link directly to this ADR so operators and agents have one canonical explanation for why `/tmp/x`, linked git worktrees, Antigravity's session `brain/<conversationId>` directory, and Claude's `~/.claude/projects/<slug>/memory/**` allow while `/tmp` itself, `.git/hooks` / `core.hooksPath`, `guardrail.toml`, and plane settings files deny.
- Any future write seam or carve-out must add a row to Section 1 with its enforcing function and test coverage before merging.
